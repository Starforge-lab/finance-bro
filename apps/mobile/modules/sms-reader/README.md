# Android SMS reader feasibility module

This local Expo module provides the read-only Android inbox path and consent-gated `SMS_RECEIVED` receiver. Android builds declare its SMS permissions and receiver so the import flow can request access after explicit user consent; declarations do not request OS permission or enable import. The durable setting defaults off, and the receiver checks it before decoding broadcast PDUs. The separate probe keeps its isolated package identity and test extras. Matching native compilation, bounded consented foreground reads and fictional parser/SQLite checks have device evidence in [the probe record](../../../../docs/android-sms-probe.md), including one manually requested cold headless callback and one unattended scheduled callback. Live receiver and multipart delivery remain unverified.

`getSmsReader()` returns `null` outside Android or when Android has not linked this module. On Android, the caller must invoke `requestPermissionsAsync()` from an explicit user action. The inbox query requires `READ_SMS`; it never requests permission by itself. It accepts a required inclusive time range of at most 90 days ending no later than now, an optional exclusive `{ dateMs, id }` cursor, and a limit from 1 to 100. Returned rows are in ascending date and platform-id order, with the platform id kept as a string. This bounds each returned batch and its requested date window; the platform provider may still scan matching rows to produce that order. The sender and body exist only in the returned in-memory result; callers must not log or persist them.

`getImportSettingsAsync()` returns the durable automatic-import setting. It defaults to `{ enabled: false, startDateMs: null }`. Call `setImportSettingsAsync({ enabled: true, startDateMs, previewEndDateMs })` only after the user separately confirms the cancellable history preview. The first enable requires positive safe-integer timestamps, with the frozen preview end no later than confirmation time, no earlier than the start, and at most 90 days after the start. This validates the preview that was actually shown rather than the later confirmation tap time; `previewEndDateMs` is not persisted. Re-enabling must use the originally confirmed start date so a saved cursor can resume without skipping messages; it may omit `previewEndDateMs` because its original range can now exceed 90 days. Disabling writes `enabled: false` synchronously and preserves that start date. A failed preference write rejects instead of reporting success.

`readInboxMessageAsync(platformId)` re-reads one original Inbox row by its canonical positive platform-id string. It requires `READ_SMS`, returns `null` only when the row is absent, and rejects provider results whose id, timestamp or row count is invalid. If access is revoked during the read, the caller receives the normal missing-permission error; other provider errors are body-free. Sender and body remain in memory only; callers must not log or persist them.

The receiver checks the persisted enabled flag before decoding broadcast PDUs. While disabled, it returns without reading the SMS payload or changing wake metadata. While enabled, it records only aggregate event count, multipart count and receipt time using private preferences; these writes are best-effort if Android terminates the process immediately. It does not inspect message text, send an event to JavaScript, parse messages, schedule work, or read the inbox. Inbox query and single-message review remain available with `READ_SMS` for explicit preview or on-demand review even while automatic import is disabled. The receiver requires the system-only `BROADCAST_SMS` sender permission to prevent other apps from injecting wake metadata.

This does not prove permission grantability on every installer or distribution channel. Android classifies `READ_SMS` and `RECEIVE_SMS` as hard-restricted permissions, which installers may need to allowlist. The probe is not evidence of Play policy eligibility, F-Droid installation behavior, reliable background execution, or a complete automatic-import flow. See the Android references for [`READ_SMS`](https://developer.android.com/reference/android/Manifest.permission#READ_SMS), [`RECEIVE_SMS`](https://developer.android.com/reference/android/Manifest.permission#RECEIVE_SMS), and [`SMS_RECEIVED_ACTION`](https://developer.android.com/reference/android/provider/Telephony.Sms.Intents#SMS_RECEIVED_ACTION).

Run `node modules/sms-reader/self-check.cjs` from `apps/mobile` to verify manifest isolation, receiver protection, Android module registration and source-level privacy guards. This does not exercise native query validation or prove runtime behavior.

The Android APK workflow also runs `:sms-reader:testDebugUnitTest` before assembly. These JVM tests exercise query validation, cursor ordering, canonical platform ids, and single-row result validation with fake cursors and fictional data. They cover missing, mismatched, invalid-date and duplicate rows, sanitized cursor errors, and cursor closure without a provider or device. They do not test `ContentResolver` selection, real permission behavior, provider pagination, receiver delivery or lifecycle recovery. Record the exact hosted result before counting this coverage as passed.
